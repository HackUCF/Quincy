# api/sinks/postgres/pauses

Database functions that record and read whether the competition is currently paused. Pausing is durable rather than in-memory: the state lives in its own table and survives an API server restart, so an operator who pauses for a lunch break and then restarts the server does not silently resume scoring. Other database subpackages consult this state to decide whether a check result should count toward a team's totals.

The table is an append-only log of state changes rather than a single mutable row. Each entry carries the new state and the Unix microsecond timestamp at which it took effect, and the current state is whichever entry has the newest timestamp. Keeping the history means the exact windows during which scoring was halted remain queryable after the fact.

The package provides an initializer, two readers, a state changer, and a maintenance query. The initializer seeds the configured starting state, guarded so that it writes only when the table is empty and is therefore a no-op on every boot after the first. One reader takes a transaction rather than the connection pool so that a caller writing scores can read the pause state and act on it inside the same transaction, with no window in which the state could change underneath it; the other takes the pool and returns both the current state and the moment it was entered, for reporting to an operator. The state changer runs in its own transaction, compares the requested state against the current one, writes nothing and reports no change when they already match, and otherwise appends a new entry. The maintenance query collapses runs of consecutive entries that repeat the same state, deleting every entry after the first in each run so the log stays a clean alternating sequence.
